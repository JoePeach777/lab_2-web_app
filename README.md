# Контрольные вопросы

## 1. Что такое модель в Django и для чего она используется?

**Ответ:** Модель в Django — это класс на языке Python, который представляет таблицу в базе данных. Каждое поле класса соответствует столбцу таблицы. Модели используются для удобного управления структурой данных через ORM без необходимости писать чистый SQL-код.

## 2. Какие типы полей вы знаете? Приведите примеры.

**Ответ:**

- `CharField` — для строковых значений, например кода валюты `USD`.
- `DecimalField` — для точных числовых значений, например курса валюты.
- `FloatField` — для чисел с плавающей точкой, например процента изменения.
- `DateField` — для хранения даты.
- `DateTimeField` — для хранения даты и времени.
- `IntegerField` — для целых чисел.

## 3. Чем отличаются параметры `blank=True` и `null=True`?

**Ответ:**

- `null=True` работает на уровне базы данных и разрешает хранить значение `NULL` в столбце.
- `blank=True` работает на уровне валидации форм и административной панели Django, позволяя оставлять поле незаполненным.

Таким образом, `null` относится преимущественно к базе данных, а `blank` — к валидации данных в Django.

## 4. Что такое миграции и зачем они нужны? Опишите основные команды для работы с ними.

**Ответ:** Миграции — это механизм Django, который позволяет синхронизировать изменения в моделях (`models.py`) со структурой базы данных.

Основные команды:

```bash
python manage.py makemigrations
```

Создаёт файлы миграций на основе изменений в моделях.

```bash
python manage.py migrate
```

Применяет созданные миграции к базе данных.

## 5. Как создать суперпользователя для доступа к административной панели Django?

**Ответ:** Для создания суперпользователя необходимо выполнить команду:

```bash
python manage.py createsuperuser
```

После запуска команды Django попросит указать имя пользователя, адрес электронной почты и пароль.

## 6. Что такое ORM? Перечислите основные методы для выполнения операций CRUD.

**Ответ:** ORM (Object-Relational Mapping) — это технология, позволяющая работать с базой данных через объекты и классы Python вместо непосредственного написания SQL-запросов.

Основные операции CRUD:

- **C — Create:** `Model.objects.create(...)`
- **R — Read:** `Model.objects.all()`, `Model.objects.filter(...)`
- **U — Update:** изменение полей объекта и вызов `obj.save()`
- **D — Delete:** вызов `obj.delete()`

Пример:

```python
currency = CurrencyRate.objects.create(
    currency_code="USD",
    rate=92.5,
    date="2026-09-20",
    change_percent=1.2
)
```

## 7. В чем разница между методами `filter()` и `get()`?

**Ответ:**

`filter()` возвращает объект `QuerySet`, содержащий все записи, соответствующие условию. Результат может содержать 0, 1 или несколько объектов.

```python
CurrencyRate.objects.filter(currency_code="USD")
```

`get()` используется для получения одного конкретного объекта.

```python
CurrencyRate.objects.get(currency_code="USD")
```

Если объект не найден, `get()` вызывает исключение `DoesNotExist`. Если найдено несколько объектов, вызывается `MultipleObjectsReturned`.

## 8. Как настроить загрузку изображений (медиафайлов) в проекте Django?

**Ответ:** В файле `settings.py` необходимо задать:

```python
MEDIA_URL = "/media/"
MEDIA_ROOT = BASE_DIR / "media"
```

В модели можно использовать поле:

```python
image = models.ImageField(upload_to="images/")
```

Также в главном файле `urls.py` необходимо настроить раздачу медиафайлов:

```python
from django.conf import settings
from django.conf.urls.static import static

urlpatterns = [
    # маршруты проекта
]

urlpatterns += static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)
```

## 9. Для чего нужен метод `__str__` в модели?

**Ответ:** Метод `__str__` определяет строковое представление объекта модели.

Он нужен для того, чтобы в консоли Django, административной панели и при отладке объекты отображались понятно и читаемо, а не только в виде технического идентификатора.

Например:

```python
def __str__(self):
    return f"{self.currency_code} — {self.rate}"
```

В результате объект может отображаться как:

```text
USD — 92.5
```

## 10. Что произойдёт, если выполнить `python manage.py makemigrations`, но не выполнить `migrate`?

**Ответ:** Django создаст файл миграции на основе изменений в моделях, но эти изменения не будут применены к базе данных.

То есть структура базы данных останется прежней. Если модель требует таблицу, которой ещё нет в базе данных, при попытке обратиться к ней может возникнуть ошибка, связанная с отсутствием таблицы.
